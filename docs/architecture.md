# Loop 架构

## 进程与职责

应用分为两个独立进程：`Loop` 是 Fyne UI，`loopd` 是后台运行时。连接时后台再启动 sing-box 子进程；使用 TUN 时后台直接连接独立的 root 授权服务，由服务启动内核，不启动普通用户的中继进程。因此“两进程”指应用角色，实际进程数会随连接方式增加。

```text
Loop / Fyne UI ──┐
                ├─ Unix Socket / HTTP JSON v1 ─ loopd ─ sing-box
loopctl / CLI ───┘                               │
                                       原生 Cocoa 菜单栏
                                                │
                                       macOS TUN service
```

- UI 只管理窗口、编辑草稿和交互任务；关闭窗口会退出整个 UI 进程。
- 后台拥有代理生命周期、模式、策略选择、配置写入和菜单栏。macOS 打包时放在独立标识的 `Contents/Helpers/loop-background.app` 中，避免 LaunchServices 把菜单栏后台误认为 UI，导致再次打开应用只激活后台。UI 消失不会停止后台或代理。
- CLI 不依赖 Fyne，可启动后台、查询状态、开关连接、切换模式和策略，并输出 JSON。
- sing-box 仍作为内置可执行文件使用，没有嵌入 Fyne 或更换内核。

## 目录

```text
cmd/
  loop/       桌面入口，也兼容管理参数
  loopd/      后台前台运行入口，可独立部署
  loopctl/    独立命令行入口，无 Fyne 依赖
  loop-tun/   macOS 提权辅助程序
internal/
  desktop/        Fyne 页面、编辑器、窗口与 UI 生命周期
  cli/            参数解析、命令分派与 JSON 输出
  control/        后台控制器、单实例、Unix Socket API、客户端与进程启动
  statusbar/      后台的 Cocoa 菜单栏，无 Fyne / OpenGL 依赖
  app/            共享操作、校验保存、订阅更新、连接切换与回滚
  autostart/      macOS 主应用登录项注册与状态读取
  profile/        配置、节点、订阅、规则、策略图与持久化
  proxy/          内核生命周期、系统代理恢复、TUN 客户端、节点延迟、网址分流与批量 HTTP 测试
  tunhelper/      提权会话、TUN 路由与临时 DNS 生命周期
  testutil/       临时配置和虚构节点
profiles/         开发配置与打包时的首次运行种子
scripts/          依赖准备、macOS 打包、内核复制与签名
third_party/
  fyne-patches/  Fyne 固定版本、校验值、补丁与维护说明（纳入 Git）
  fyne/          自动重建的完整 Fyne 源码（Git 忽略）
```

`profile` 不依赖 UI、应用服务或进程管理。`proxy` 不依赖 Fyne 或配置存储。`app` 组合这些能力，并通过 `RemoteOperations` 支持 UI 转发写操作。`control` 负责操作串行化和后台状态；它不导入 `desktop`。`statusbar` 通过操作模型调用后台，无需创建 Fyne 窗口或渲染器。

标题与说明共用 `desktop/info_row.go` 的 `infoRow` 组件。`newListRow` 用于更多 / 规则分类、节点订阅与节点列表、策略组与成员、测速选点；`newSectionHeader` 用于节点来源标题、规则内容标题、策略内容标题、自启和菜单栏设置。两种尺寸统一管理内边距、2 点文字间距、可选图标 / 左侧控件、右侧操作位及空说明隐藏；列表文本单行省略，内容标题说明可换行。品牌区也复用底层文字布局。页面通过 `setText`、`setIcon`、`setLeading`、`setTrailing` 更新具名内容位，不依赖组件内部容器索引。标准 List 继续管理选中、悬停、键盘与回收，管理行独立保留右键回调。

运行中切换 TUN 通过 `desktop → control set_tun → app.SwitchTUN` 执行，与连接、分流模式及策略编辑共用后台操作锁。先保存并编译目标接管设置，再停止旧后端；`Stop` 完成系统代理恢复或 TUN / 临时 DNS 清理后才启动新连接。启动失败时先清理，再恢复原开关并尝试重连；清理或恢复失败时停止继续启动并报告错误。事务不随前端断开而取消，忙状态期间禁用 TUN 开关；完整配置调试模式仍由文件管理接管方式。

macOS UI 的系统字体通过可选 `SystemFontResource` 使用 CoreText 测量和绘制：苹方用于常规/加粗文字，Menlo 用于编辑器，Emoji/符号由系统回退。原生字体缓存最多 48 项；文字布局和图像上下文逐次释放。Fyne 仍负责组件、窗口、布局与 OpenGL 纹理，Go 业务层和后台不变。普通输入框、换行和节点名称省略均使用同一套原生测量。

其他平台或未选择原生绘制的字体仍使用 Go 路径：有界缓存共享不可变字库表，仅配色/尺寸不同的主题范围复用映射；文件字体通过 `FontFileResource` 直接读取 TTC 表，回退按需加载。配置编辑器首次进入时构建，文件未变则保留内容、光标和撤销历史。启动稳定后仅回收一次临时内存，没有周期性强制 GC。字体补丁由根模块 `replace` 固定，`make` 构建/测试和打包脚本会自动准备，直接运行 Go 命令前先执行 `make prepare`。仓库只跟踪补丁，完整依赖从固定版本和校验值重建；本地修改会先要求通过 `make update-fyne-patch` 保存，避免被覆盖。升级 Fyne 时需复核，维护步骤见 [Fyne 补丁](../third_party/fyne-patches/README.md)。测量方式与结果见 [UI 内存](ui-memory.md)。

网址分流测试由 `desktop/routing.go → app.Service.TestRouting → control test_routing → proxy.RoutingProber` 执行。后台在串行操作锁内编译已保存模式、规则、DNS 和节点选择，临时内核只暴露随机端口、随机口令的 loopback mixed 入站，禁用 TUN、共享缓存与管理监听器。通过 SOCKS 请求 HTTP / HTTPS，不跟随重定向，不读取响应体。测试进程的诊断流仅在内存中提取同一连接 ID、目标地址的规则命中与实际出站事件，再解析 selector 路径并映射节点名称；不自行重写分流匹配器，也不依靠轮询活动连接。该解析与打包内核的日志格式配套，未取得实际出站事件时显示未知，不凭策略默认值猜测。正常退出、取消和超时均终止并等待子进程、清除临时配置；测试失败不覆盖后台连接状态或已有内核错误。

批量 HTTP 测试通过 `desktop/benchmark.go → app.RunBenchmark → control benchmark → proxy.BenchmarkProber` 执行。RPC 只接收参数和节点稳定键，后台解析真实节点并在独立内核中通过认证用户强制各节点的出站；不指定节点时编译已保存分流快照。每个节点顺序执行完整的一组并发请求，读取并丢弃完整响应体，按单请求超时和每任务限速控制工作池。统计直方图固定为 2048 个桶，进度每 250 ms 发布不可变快照，UI 沿用状态轮询读取；job ID 与单调结果合并防止延迟状态覆盖最终结果。批量任务由请求/后台生命周期取消，不沿用普通写操作的 3 分钟期限；用户取消保留已完成统计，后台忙状态释放时保留真实连接与内核错误。

策略组编辑采用 `strategy_editor.go` 的两级草稿：主弹窗只显示已配置项，点击添加后才创建可搜索的 Tree / Check 选择器；自动来源保持为配置项，不展开成节点快照。主草稿深拷贝各成员数组，选择器确认后去重追加，取消不修改主草稿；主弹窗保存时才进入现有 `RunPolicies` 事务。列表行复用 `infoRow`，移除回调绑定当前稳定 ID，已有成员在选择器中禁用。

## 生命周期

打开 UI 时先尝试激活已有窗口，否则确保后台存在，并附加到其状态。后台使用单实例文件锁，不会因为第二次打开应用重复启动内核。UI 也有独立实例锁和本地激活接口。

关闭 `×` 会确认未保存草稿、取消 UI 请求、释放窗口并退出 UI 进程；不发送停止连接命令。后台接受的连接和规则应用事务使用后台自己的 context，即使请求方退出也会完成或回滚。节点延迟和网址分流测试使用请求 context，关闭 UI 或取消测试会回收独立测试内核。

菜单栏“显示主窗口”激活已有 UI，或重新启动 UI 进程。菜单栏“退出 Loop”优先让已有 UI 确认未保存草稿，再退出后台；没有 UI 时直接停止后台。`⌘Q` 同样执行完整退出。CLI `daemon stop` 直接停止后台，不等待 UI 草稿确认；UI 保留草稿并显示后台不可用，关闭重开可重新附加。信号 SIGTERM / SIGINT 只结束接收它的角色：后台清理代理，UI 仅清理界面。

登录自启继续使用 `SMAppService.mainAppService`，启动主应用后确保后台存在；不意味着自动连接代理。登录自启本身不安装 root 服务；TUN 首次使用另行安装授权服务。

## 本机 API 与并发

后台在当前用户私有的临时目录创建 `control.sock`，目录权限 0700、Socket 权限 0600，无 TCP 监听。目录名由状态目录路径哈希得到，避免 Unix Socket 路径过长。不同状态目录可运行独立实例；独立实例也应使用不同的 profiles、端口和接管设置。

- `GET /v1/status`：协议版本、实例 ID、PID、连接/忙碌状态、模式、策略成员与菜单偏好。不返回节点凭据和订阅 URL。
- `POST /v1/action`：共享的操作模型，返回 `ok / error / status / result`。拒绝未知字段、多个 JSON 对象和超过 8 MiB 的请求。
- 操作串行执行，忙碌时返回 HTTP 409。CLI 使用非零退出码和 `ok:false` 报告失败。
- 客户端附加后绑定后台实例 ID。后台重启后，旧客户端的写入被拒绝，防止旧窗口修改新实例。
- 配置保存保留内容基线检查、原子替换、0600 文件权限和最近一次备份。
- 旧 CLI 文件修改参数持有与后台相同的锁，只允许离线执行；在线选择使用 `policy select`。

UI 每秒读取后台快照，刷新主线程状态并保留编辑草稿。UI 中的连接、配置、规则、节点和订阅写操作均经后台执行；读文件仍使用现有 Store。用户手工外部编辑不受后台互斥锁管理，保存时的基线检查仍会检测冲突。

规则、模式和策略在线切换复用 `app` 的停止、启动、失败回滚流程。规则校验失败保留原连接；自动分流在线保存成功后重连；全局模式仅保存，切回自动分流生效。后台自行持有事务 context，UI 的退出不会破坏恢复连接。

应用身份、默认状态目录和旧版迁移集中在 `app/identity.go`。安装版首次使用默认目录时复制 MiniProxy 的持久配置，先完整写入临时目录再发布，保留旧源文件与新目录已有数据；主题偏好在 Fyne 读取新 ID 前导入。代理恢复记录、运行配置和锁不跨应用迁移，登录项由用户在新应用中重新注册。

主配置仍为 `profiles/config.json`，节点和订阅独立保存。菜单栏偏好由状态目录的 `desktop.json` 保存，第一次附加 UI 时迁移旧 Fyne 偏好；主题由 UI 自己保存。运行配置 `runtime/config.json` 是含凭据的生成物，不回写主配置。

## 构建与验证

```sh
make run            # 构建全部角色后打开 UI
make build          # UI、daemon、CLI、TUN helper
make test           # 全量回归 + race detector
make test-headless  # 无 CGO 的后台/核心包测试，不编译 Fyne
make vet
make package        # 当前 macOS 架构的完整应用和 ZIP
```

控制器和 Socket 测试使用虚构节点与替身后端，不修改系统代理或 TUN；配置检查集成测试使用 PATH 中的 sing-box，缺少时跳过。覆盖客户端退出后事务继续、重复连接幂等、多个客户端同步、写操作互斥、单实例/权限、旧实例拒绝、退出清理、规则回滚、菜单模型、CLI JSON 与 UI 偏好同步。

目前交付目标为 macOS。Unix Socket 控制层可用于其他 Unix 平台；Windows 需要补充 IPC/进程适配。Android 仍需要 VpnService/libbox、授权与前台服务，不能直接沿用桌面子进程和 macOS helper。

策略定义编辑通过 `desktop RunPolicies → app.Service.SavePolicies → control save_policies` 串行执行，与规则保存共用 `app/document_apply.go` 的校验、备份、实际配置检查、重连和回滚事务。UI 退出不取消后台的应用及恢复流程；全局代理继续应用策略修改，直连模式只保存。`profile.PolicyGroup` 使用独立的 `builtins` / `nodes` / `sources` / `groups` 描述内置、明确节点、动态来源与组引用，保留旧 `all_nodes` / `filter` 兼容；节点成员带来源元数据供分组显示。成员先去重，明确节点不受动态正则筛选影响。编辑拒绝移除当前选择，必要时固定旧的隐式首项，避免新增成员意外改变出口。DIRECT / REJECT 编译成原生 direct / block 出站，参与普通 selector 嵌套、菜单切换与分流诊断；不把内置项送入节点延迟探针。成员编辑用标准 Fyne Tree 与 Check，列表虚拟化避免订阅节点数量放大控件开销。

Available 仅是首次创建的组名，与其他组使用同一套成员、图校验和删除依赖检查。主配置 `default_policy` 显式指定全局代理出口（旧配置隐式 Available，可显式清空），UI 的设为默认通过同一运行中策略事务保存；全局模式、旧 proxy 别名和新增规则订阅的下载出口读取该字段。删除默认组清空角色，不选取替代组、不重新播种；自动分流仅检查真实依赖，全局模式缺少默认组时明确失败。已有规则 / DNS 的明确组引用须先处理，当前全局连接缺少新默认组的编辑会在停止前失败并恢复源文件。Available 的选择与其他组一样保存在 policy-selections.json，旧原始全节点组读取 selection.json 仅用于兼容，CLI 节点选择同步两份状态并在写入失败时恢复旧兼容文件；订阅更新保护真实策略选择，不受已删除组的旧选择记录阻塞。

TUN 授权服务由 `launchd` 按需唤醒，普通用户的 `loopd` 直接通过 Unix Socket 连接系统服务。`loop-tun` 可执行文件用于安装、更新和管理服务，常规连接不启动它。安装时将辅助程序和内核复制到 root 所有的固定路径；服务校验 Unix Socket 对端 UID，只运行固定内核，并将用户读取的规则快照写入本次私有工作目录。配置白名单限制入站、出站与 DNS 类型，拒绝执行插件和外部文件读取。控制连接 EOF 会先停止内核、释放 DNS 和私有文件，再释放唯一活动连接位并关闭服务端连接；后台半关闭写端请求停止，继续读取到服务端 EOF 才完成断开，确保紧接着的重连不会与清理竞态。后台崩溃会关闭控制连接并触发同样的服务端清理；服务没有连接约 5 秒后退出，Socket 由 launchd 保留供下次唤醒。服务协议或内核 SHA 变化才触发安装更新，普通 UI 更新和配置编辑不触发提权。测试通过可注入的同一服务端实现与替身内核验证连续连接、UID 拒绝、固定内核、并发互斥、快照限制和 EOF 清理确认；真实系统安装需管理员授权。

### 本地代理入口

主配置 `proxy_ports` 是端口设置的唯一来源，保存默认端口、全局端口与全局入口开关。`profile` 编译器生成 `mixed-in` 和可选 `global-in`；TUN 仍独立生成 `tun-in`。首页模式只覆盖默认入口和 TUN，全局入口按 inbound 标签优先匹配专用路由与 DNS，并引用实际默认策略。直连模式启用全局入口时仍编译策略；关闭全局入口后保留原有纯直连行为。

`internal/inbound` 统一验证入口身份、本机地址、端口范围和重复端口。系统代理始终按 `mixed-in` 选取地址，后台启动检查所有启用端口；TUN 服务执行相同的入口约束。分流诊断只使用隔离的默认入口，测速保持自己的随机端口。

`save_ports` 操作在后台操作锁下执行，仅允许修改 `proxy_ports`。先验证新端口可绑定（跳过当前内核持有的地址），再复用主配置备份、校验、重启和恢复事务；该事务不随前端断开取消。端口变化在所有首页模式下均应用，直连模式下策略变化也会在全局入口开启时应用。UI 通过共享文档控制器自动保存，避免与 JSON 草稿、规则和策略修改发生覆盖。
