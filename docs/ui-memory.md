# UI 内存优化（0.16.2–0.16.4）

2026-11-13，macOS 15.7.3 / Apple Silicon，Go 1.27.1、Fyne 2.8.2。
使用独立临时 profiles/state、一条虚构节点、1120 × 760 窗口；不连接代理，
不修改安装版的节点、配置、后台或系统代理。

## 0.16.4：macOS CoreText

2026-11-14，沿用相同 macOS/Go/Fyne、1120 × 760 窗口和显示缩放。
两版发行构建分别使用独立临时 App、相同虚构节点/中文策略、独立 profiles/state，
后台加 `--no-tray`；不连接代理。`vmmap -summary` 测 UI physical footprint，
没有给发行构建加入 profiler 或额外强制 GC。

| 场景（依次访问） | 0.16.3 Go 字体绘制 | 0.16.4 CoreText |
| --- | ---: | ---: |
| 首页 | 96.8 MiB | 54.1 MiB |
| 配置页（包含中文策略名） | 111.0 MiB | 60.6 MiB |
| 节点页（包含国旗/火箭） | 112.9 MiB | 60.9 MiB |
| 该次访问的瞬时峰值 | 168.5 MiB | 118.6 MiB |

首页下降约 44%，配置/节点页下降约 45–46%。最终 ZIP 中二进制另用独立 App
重新签名测试（逐个 Mach-O section 内容核对相同），首页另一次采样为 58.2 MiB、配置页 62.9 MiB；
运行间会有波动。这些数字只包含 UI 进程，
后台与连接后的 sing-box 应单独计算；窗口尺寸、节点数量和显示缩放仍会影响结果。
测量值不能作为固定上限。

实现由 `SystemFontResource` 明确选择原生路径：苹方 Regular/Semibold、
Menlo Regular/Bold 和 AppleSymbols 交给 CoreText，中文、Emoji 与缺字回退由系统处理。
测量、RGBA 绘制、列表省略号裁剪使用同一个引擎；裁剪不拆开组合字符/国旗/ZWJ Emoji。
Fyne 继续负责组件、布局、纹理和窗口。不是把 UI 改为 Cocoa 控件，也没有加入 WebView。
其他平台/自定义字体继续使用原来的 Go 解析与有界缓存。

CoreText 的有界缓存最多保留 48 个字体对象，不缓存用户文字或 CTLine。
每次调用使用 autorelease pool 并释放布局、图像上下文和颜色空间；C 同步借用
Go 的 RGBA 缓冲，不持有 Go 指针。字体文件不打包、不修改。

另用独立诊断构建做 8 轮六页面轮换与深浅色切换：回到首页后 Go 堆约
5.3 MiB（自然 GC 后采样；不同采样时刻约 4–10 MiB），UI footprint 约
70 MiB，峰值约 130 MiB。heap profile 已没有 go-text 大型字体表。
该诊断构建含周期 heap profile 写入，不能与发行构建的单页数字混为一谈。

已验证：中文/英文/Emoji、系统深浅色、字重/斜体/符号、透明度、正立方向、
Tab 与 ASCII 等宽网格、1x/1.5x/2x 裁剪一致、并发缓存淘汰；Fyne 包装/截断标签
与普通 Entry 原生宽度命中测试。配置编辑器保留草稿、光标、撤销/重做。

已知继承限制：PrettyView 2.7.0 按 rune 计固定列，紧凑 JSON 中中文字符串后仍有
其他字段时可能对齐重叠，中文内部光标列也受该网格限制。用相同输入对照 0.16.3
确认该问题原已存在；本次没有改写编辑器的 Unicode 列模型，不能把普通 Entry 的
命中测试等同于编辑器所有 Unicode 编辑行为。点击格式化可将字段分行，减少重叠。

`make test`（含 race 与原生回归）、`make test-headless`、`go vet ./...` 通过。
打包版本为 0.16.4/build 32；诊断代码/进程验证后移除，安装版及其代理未改动。

## 后续空间的对照测量

0.16.3 的相同构建、1120 × 760 窗口、相同显示缩放，独立进程启动，
2 秒后回收一次启动临时内存、8 秒后采样（不连接后台或代理）：

| 窗口内容 | Go 存活堆 | UI physical footprint |
| --- | ---: | ---: |
| 空白 Fyne 窗口 | 1.2 MiB | 54.1 MiB |
| 英文标签和启动按钮 | 4.1 MiB | 54.3 MiB |
| 苹方中文标签和启动按钮 | 31.9 MiB | 80.8 MiB |
| 完整首页与其余页面初始化 | 32.8 MiB | 95.7 MiB |

完整首页的 heap profile 中，约 23 MiB 为字体原始表的解析存储。
空白窗口也有约 54 MiB footprint，包含 Cocoa/OpenGL 上下文、图形缓冲、
Go 运行时和进程其他资源；这只是当前环境的基线，不是所有 Fyne 应用的硬下限。
简单中文窗口与完整首页的 Go 堆相差不足 1 MiB，因此不能把未打开的页面
误认为当前剩余的大头。后续方向：

- 延迟创建其他页面、管理离开页面后的纹理寿命：主要改善访问很多页面后的
  峰值/留存，首页的收益需另测。不能丢失编辑草稿与撤销历史。
- 调整中文字体表读取/字形解析，或实验 macOS CoreText 文字后端：
  针对剩余字体堆。当前“使用系统字体”只是读取苹方文件，仍由 Go 解析、
  Fyne 排版绘制，并未调用系统文字绘制。后端替换需验证测量与绘制一致、
  混合字体/Emoji、换行、光标、搜索选择与深浅色，不能只替换字面显示。
- 若目标显著低于当前空白 Fyne 基线，应单独验证 macOS 原生控件前端：
  Go 后台、CLI 和业务层可继续使用现有实现，UI 需 Objective-C/CGo 适配，
  跨平台维护方式会变化。其实际节省多少应由原型测量，当前没有结果。

本轮只做诊断与记录，不替换 UI 技术或修改安装版进程。诊断代码和临时进程已移除。

## 0.16.3 进一步优化

0.16.2 剩余的 Go 堆主要是两个苹方字重约 25 MiB 的 SFNT 原始副本、
解析后的字库表，以及颜色主题范围分别创建的字形缓存。0.16.3：

- 增加可选 `FontFileResource`，按文件和 TTC 字体索引直接解析表，
  不再常驻一份独立 SFNT 原始副本，也不改动系统字体文件。
- 字体映射按实际字体资源和回退样式复用，颜色/尺寸主题范围不再重复
  分配字形缓存。不同字体与实际不同的映射仍使用独立可变 Face。
- 回退字体仅预读小型字符映射，确实遇到对应缺字才解析完整字库。
  配置编辑器中的中文复用主界面的苹方；国旗、Emoji、符号继续可用。
- 启动稳定后仅执行一次临时内存回收，没有周期性强制 GC。

同条件诊断进程的 Go 存活堆从约 **76.5 MiB 降至 33.3 MiB**。
发行二进制用独立临时 App 实测，未加入 profiler 或外部强制 GC：

| 场景 | 0.16.2 | 0.16.3 |
| --- | ---: | ---: |
| 首页 | 141.5 MiB | 97.0 MiB |
| 打开配置页 | 152.8 MiB | 111.4 MiB |
| 再打开国旗/Emoji 节点列表 | 未记录 | 116.0 MiB |

0.16.3 配置页额外包含可见的中文策略名称，节点列表包含国旗和火箭 Emoji，
实际窗口均确认显示正常。该轮访问中的 UI 瞬时峰值约 171 MiB。
另用含相同中文策略和 Emoji 节点的独立诊断窗口执行 8 轮六页面轮换与
深浅色切换：第 4/8 轮 Go 存活堆约 42.1/43.2 MiB，回首页后约 43.4 MiB；
UI 空闲 footprint 约 121.7 MiB，瞬时峰值约 194.7 MiB。
这些是相同窗口/显示条件下的测量，不能保证所有页面和所有设备低于 100 MiB。
大配置、更多文字/图片、窗口尺寸和系统图形缓冲都会影响结果。

文件字体读取/更新、无 Content 副本、字符映射、主题范围共享与不同字体隔离，
以及回退按需加载均有回归测试；完整 `make test`（含 race）通过。

以下保留 0.16.2 的定位过程与对照结果。

## 原因与修复

Go heap profile 显示，优化前约 90% 的存活堆来自字体路径。
Fyne 按文字样式/主题范围分别解析主题字体、Emoji 和符号字库；
页面渲染和外观切换又会产生新实例，长期保留大型字库表。
这不是后台 sing-box 的占用，也不主要是窗口图形缓存。

- Fyne 本地补丁按内容复用不可变字体表，缓存最多 16 项。
  每个消费者仍保留独立可变 Face，避免字号/变体设置相互影响。
  缺字时才加载系统语言回退字体。中文、不同字重和 Emoji 均保留。
- macOS 字体加载只读取 TTC 目录、名称和需要的两个苹方字重，
  不读取整个约 75 MiB 的字体集合；提取结果一次分配精确容量。
- 配置编辑器首次进入时加载。刷新时文件未变不再反复调用 SetData，
  保留草稿、光标、撤销/重做历史。规则页可在未打开编辑器时保存，
  首次进入配置页读取最新主配置。

Fyne 改动范围与依赖重建方式记录在 [补丁说明](../third_party/fyne-patches/README.md)。
仓库仅跟踪固定版本、校验值与补丁；完整源码通过 `make prepare` 重建到忽略目录。
没有修改共享的 Go module cache，也没有在发行版加入 profiling 监听端口。

## 测量

诊断进程在相同首页和虚构配置上运行，等待初始化完成后 GC，
用 runtime.MemStats/heap profile 测 Go 堆，`vmmap -summary <UI_PID>`
测 physical footprint（包含压缩内存，比单看 `ps` RSS 更适合此问题）。

| 首页稳定状态 | 优化前 | 优化后 |
| --- | ---: | ---: |
| Go 存活堆 | 341.2 MiB | 76.5 MiB |
| UI physical footprint | 412.2 MiB | 134.8 MiB |

最终发行二进制另用独立测试 App 启动，无 profiler、无手动 GC：
首页约 **141.5 MiB**，首次打开配置页约 **152.8 MiB**。
实际使用受节点数量、配置内容、窗口大小、显示缩放和系统内存压力影响。
峰值会高于空闲值，不将 Go 堆等同于整个进程的内存。

另外执行 8 轮六个页面轮换 + 深浅色切换，期间打开配置编辑器。
字体实现对照版本的 Go 堆随轮次持续增长至数 GiB；
修复版第 4/8 轮分别约 78.8/79.9 MiB，没有同样的持续增长。
这轮压力测试测得 UI 瞬时峰值约 338 MiB；回到首页后的空闲值降至约 177 MiB。
测试使用的诊断程序与进程在验证后移除。
